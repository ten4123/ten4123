# 디자인 도우미 공통 규약

모든 모듈 에이전트(M1~M8)와 코치(M0)가 따르는 규칙입니다. 에이전트는 작업을 시작하기 전에 이 파일을 읽습니다.

## 1. 프로젝트 폴더

```
projects/<slug>/
  project.md          # 프로젝트 개요: 도메인, 사용자, 검증 방식, 브리프 위치, 현재 모드·단계
  m1-problem.md       # M1 문제 정의
  m2-context.md       # M2 맥락 수집
  m3a-process-research.md  # M3-a 작업기 리서치
  m3b-domain-research.md   # M3-b 도메인 리서치
  m3-references.md    # M3 레퍼런스 카드 모음(감사 결과 포함)
  m4-options.md       # M4 발산 대안
  m5-critique.md      # M5 수렴·크리틱
  m6-spec.md          # M6 구체화 스펙
  m7-validation.md    # M7 정성 검증 계획·결과 종합
  decisions.md        # M8 결정 로그 (append-only)
  learning-log.md     # M0 사용자 학습 기록 (append-only)
```

- 산출물이 이미 있으면 덮어쓰지 않습니다. `## vN (YYYY-MM-DD)` 섹션을 추가해 갱신합니다.
- 관찰은 `O#`, 레퍼런스는 `REF-###`, 대안은 `OPT-<O#>-<letter>`, 결정은 `DEC-###`로 ID를 붙여 서로 참조합니다.

## 2. 프로세스 단계

① 문제 검증 · ② 맥락 수집 · ③ 레퍼런스 · ④ 발산 · ⑤ 수렴 · ⑥ 구체화 · ⑦ 검증(정성 피드백) · ⑧ 학습 기록

## 3. 레퍼런스 4종

| 종류 | 질문 | 예 |
|---|---|---|
| 비주얼 | 어떻게 보이나 | 화면 스크린샷, 색·타이포 사례 |
| 패턴 | 어떻게 동작하나 | 일괄 액션 바, 목록-상세, 필터 칩 |
| 근거 | 효과가 있었나 | 연구, A/B 결과, 사용성 테스트 결과 |
| 원칙 | 왜 맞나 | HIG, NN/g 휴리스틱, 토스 제품 원칙 |

## 4. 레퍼런스 카드

```yaml
id: REF-001
type: 비주얼 | 패턴 | 근거 | 원칙
title: ""
source: "<링크>"
designer_or_org: ""
problem_it_solves: ""
applies_to: [O1]
evidence: "출처의 근거(짧은 인용)"
why_needed: "이 요소가 우리 문제에 꼭 필요한 이유. 없으면 채택하지 않음"
cost: "가져오면 늘어나는 것(기능·정보·학습 비용)"
how_to_apply: ""
confidence: 0.0
```

## 5. 결정 로그 카드

```yaml
id: DEC-001
date: YYYY-MM-DD
question: ""
options_considered: [OPT-O1-a, OPT-O1-b]
chosen: OPT-O1-b
why: "원칙·피드백 근거"
rejected_because: {OPT-O1-a: ""}
feedback_source: ""
revisit_if: ""
```

## 6. 품질 규칙 (모든 에이전트 공통)

1. **신뢰도 표기**: 주장마다 0.0~1.0을 붙입니다. 디자이너 본인이 쓴 1차 출처는 높게, 2차 요약은 낮게 줍니다.
2. **출처 정직성**: 확인한 것만 씁니다. 원문을 열지 못하고 검색 발췌만 봤다면 그렇게 밝히고 신뢰도를 낮춥니다. 기억으로 빈칸을 채우지 않습니다.
3. **가설과 사실 구분**: 사용자 확인 전의 관찰은 "가설"로 표시합니다.
4. **원칙 언어**: 문제와 평가는 가능하면 "어떤 원칙을 어떻게 어기는가/지키는가" 형식으로 씁니다.
5. **바꿀 것만 바꾸기**: B2B 숙련 사용자의 익숙함(열 순서, 용어, 위치)은 자산입니다. 변경을 제안할 때는 그 비용을 함께 적습니다.
6. **산출물 끝 형식**: 모든 산출물은 `## 요약`(3줄 이내), `## 신뢰도`, `## 주의사항`, `## 다음 단계 제안`으로 끝냅니다.
7. **민감 정보**: 환자명·등록번호 같은 실제 개인정보는 산출물에 옮기지 않습니다. 더미 값으로 바꿉니다.

## 7. 웹 접근

- WebFetch로 원문을 먼저 시도하고, 실패하면 WebSearch 발췌로 대체합니다(신뢰도 하향).
- 검색은 기본 `standard` 모드로 하고, 찾기 어려운 경우에만 `extended`를 씁니다. 여러 검색은 한 번에 묶어서 보냅니다.
