# 04. 보강 조사 종합: 디자이너 SNS·블로그 작업기 (a1·a2·a3)

> 입력: `research/a1-sns-global-designers.md`(해외 20명), `research/a2-sns-korea-designers.md`(국내 22건), `research/a3-b2b-clinical-designers.md`(B2B·임상 22건)
> 방식: 리서치 에이전트 3개 병렬 실행 → 오케스트레이터가 종합
> 한계: 세 조사 모두 **웹 검색 발췌만** 사용했다(원문 페이지 접근 차단). 카드별 신뢰도는 0.3~0.85다.

---

## 1. 세 갈래의 작업 방식

| 축 | 해외 크래프트 계열 (Linear·Arc·Notion·Figma) | 국내 (토스·당근·LY·배민) | B2B·임상 (Epic·Bloomberg·Abridge·NN/g) |
|---|---|---|---|
| 출발점 | 감각과 문제의식("craft over process") | **원칙 위반으로 문제를 정의**(Easy to answer, One thing per page) | **현장 관찰**(Epic은 디자이너 전원 병원 방문, Abridge는 의사 shadowing) |
| 발산 | **동작하는 프로토타입을 많이** 만든다(Jason Yuan "99 No's for a single Yes", 코드 직행) | 시안을 넓히기보다 **가설 1개를 뾰족하게** 세운다 | 과업 단위로 분해한 뒤 패턴을 적용한다 |
| 수렴 | taste, 데모 반복, 스트레스 테스트 | **원칙 렌즈**, 정성 타이브레이크 | 익숙함 존중(바꿀 것만 바꿈), 휴리스틱 |
| 레퍼런스 | "왜 좋은가" 분해 노트, 다른 분야 | **레퍼런스는 독이 될 수 있다**(요소마다 필요성 감사) | 가이드라인·연구 근거(경고 피로, Tall Man) |
| 검증 | 크리틱 문화(roast, 크리틱 형식 6종) | **사용자를 직접 만난다**(카페 게릴라, 본사 초대). 사내 테스트는 믿지 않는다 | RITE(3명 → 수정 → 새 3명), think-aloud |
| 신뢰도 | 0.65 | 0.8 | 0.7 |

## 2. 핵심 통찰 (프레임워크에 반영할 것)

1. **레퍼런스 수집 에이전트에는 "감사(audit)" 단계가 반드시 필요하다.** (0.8)
   토스의 「독이 되는 레퍼런스 활용법」은 남의 화면을 참고할수록 기능이 늘고 핵심이 묻혔다고 회고한다. 따라서 레퍼런스는 모으는 것보다 **"이 요소가 우리 문제에 꼭 필요한가"를 거르는 것**이 중요하다. M3 레퍼런스 카드에 `why_needed`와 `cost` 필드를 추가한다.
2. **"원칙 위반 문장"이 문제 정의의 가장 실용적인 형식이다.** (0.8)
   예: "처방 테이블은 *Recognition over recall*을 어긴다. CDSS 경고가 툴팁 안에 숨어 있다." 이렇게 쓰면 M1 산출물과 M5 수렴 기준이 같은 언어를 쓰게 된다.
3. **정성 검증은 소수를 반복해서 만나는 방식이 기준이다.** (0.8)
   토스의 "1명이라도 모르면 보류", RITE의 "3명 → 수정 → 3명"이 이 방식이다. 사내 동료 테스트는 통과로 치지 않는다. ePRIS처럼 A/B 테스트가 없는 B2B 환경에 그대로 맞는다.
4. **발산 방식은 프로젝트 성격에 따라 고른다.** (0.7)
   크래프트·인터랙션 문제라면 프로토타입 다수안(해외식), 업무·정보 문제라면 가설 1개와 원칙(토스식)을 쓴다. ePRIS는 정보 위계와 상태 표현이 핵심이므로 **토스식을 기본으로 하고, 상태 표현(O1)에만 다수안 발산**을 권한다.
5. **B2B 숙련 사용자에게는 익숙함이 자산이다.** (0.75)
   Bloomberg는 버튼 위치 하나도 신중하게 바꾼다. 약국 시스템에서 가장 많이 위반되는 휴리스틱은 일관성이다. 기획서가 종이 처방전 배치를 유지하려는 이유도 여기서 설명된다. **바꿀 것만 바꾼다**는 원칙을 M5에 추가한다.

## 3. 검증 (논리·사실·완전성·편향)

- **편향**: 국내 자료의 15/22가 토스이고, 해외 자료는 크래프트·디자인 엔지니어링 계열에 몰려 있다. 그래픽·BX 디자이너와 국내 B2B(EMR) 작업기는 거의 없다.
- **사실**: 인용문은 검색 발췌에서 가져왔다. 원문 맥락을 확인하지 않았으므로 프레임워크 근거로 쓸 때는 링크를 함께 적는다. "당근 16%→27%" 수치와 Emil의 모션 규칙은 2·3차 출처다.
- **완전성**: Mobbin·Pinterest 활용 1인칭 작업기, 와이어프레임에서 하이파이로 가는 단계별 작업기, 국내 크리틱 운영기는 확보하지 못했다. 각 리서치 문서의 "공백" 절에 정리되어 있다.

## 4. 종합 신뢰도: **0.75**

- 0.8 미만인 항목은 해외 크래프트 계열(0.65)과 발산 방식 선택 기준(0.7)이다. 공통 약점은 원문을 확인하지 못한 것이다.
- 다음에 할 일: 사용자가 원문을 직접 열어 확인할 링크 5개를 고르거나(§5), ePRIS에 적용해 보면서 유효성을 검증한다(실전 검증이 더 강한 근거가 된다).
