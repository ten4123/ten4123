### 1. 상태 차원 정의

처방 행 하나는 아래 **4개의 독립된 차원**을 동시에 가진다(직교). 화면 표현은 차원마다 다른 채널을 쓴다. 그래야 하나가 다른 하나를 가리지 않는다(C2 해결).

#### 1-a. 처리 상태 (워크플로, 앱이 소유) `S-WF`

| ID | 이름 | 의미 | 진입 조건 | 적용 약국 | 근거 |
|---|---|---|---|---|---|
| S-WF-00 | 미처리 | 검토자, 감사자, HD가 모두 비어 있음(NULL). 세부계획의 "[접수]"에 해당 | 처방 접수 시 초기 상태. 또는 저장취소로 되돌아온 상태 | 전체 | 원안 p.15 "NULL" |
| S-WF-01 | 문의/HD | 약사가 의사에게 문의 중이거나 보류(Hold)한 상태. **1차 결재이며 보류 성격** | 문의/HD 버튼 | 항암제조제2 | 원안 p.13, 10/21 |

| ID | 표기 | 의미 | 체크박스 | 근거 |
|---|---|---|---|---|
| S-OD-00 | (없음) | 정상 | 활성 | — |

### 2. 약국별 전이표

**표기**
- `→ S-WF-xx` 전이 / `⚠→` 경고를 확인한 뒤 전이 / `✕(사유)` 불가 / `—` 버튼 없음
- 액션: **A-HD** 문의/HD, **A-RV** 검토 저장, **A-AU** 감사 저장, **A-UN** 저장취소. 선택 관련 액션은 §3에서 다룬다.

- A-UN의 목적지는 G-07(**직전 이벤트 되돌리기**)에 따른다. 괄호는 이력별 목적지다.

### 4. 저장취소 이력 보존 제안 (F17) ⚑ PM 확인 필요

- **문제**: 원안은 저장취소 시 "이름 삭제"만 정의한다(p.10, p.15). 누가 감사했고 누가 취소했는지가 사라진다. 이는 원칙 "놓치지 않게"와 책임 추적에 어긋난다. R-062(감사 기록 2년 보관, 2차)와도 맞지 않는다.
- **제안**: 행마다 **추가만 하는 이벤트 이력**을 둔다. 각 이벤트는 `{event_id, 처방 키, 액션(HD/RV/AU/UN/ACK), 수행자 사번, 시각, 이전 S-WF, 다음 S-WF, 배치 ID, 취소 대상 event_id}` 형태다.
  - 화면의 "현재 검토자/감사자" 칸은 지금처럼 비운다. 원안과 같은 모습이다.
  - 이력은 지우지 않는다. S-FL-07 아이콘을 누르면 바텀시트로 "감사 김약사 10:02 → 취소 이약사 10:15" 같은 이력을 보여준다(이름은 더미).
  - G-07(직전 이벤트 되돌리기)은 이 이력이 있어야 구현할 수 있다. **이력 보존과 저장취소 규칙은 함께 결정해야 한다.**
- **범위 영향**: 서버 테이블과 API가 추가되고, 이력 바텀시트 화면 1개가 생긴다. BESTCare 연동 시 취소 반영 방식(서명 해제? 이력?)은 원안 p.23에 정의가 없다(Q-05).
- 신뢰도 0.7(필요성), 0.5(공수 영향 추정).

### 1. 좌측 고정 영역과 정보 위계

```
┌─ 고정 영역 (180px) ───────────────────────┬─ 가로 스크롤 영역 ──────────────────────────────
│ 바 8 │ ☐ 체크 44 · 처리 표지 32 │ DC 96     │ 약품명 │ 용법 │ … │ 검토자(이름·시각) │ 감사자(이름·시각) │ …
└──────┴──────────────────────────┴──────────┴──────────────────────────────────────────────
```

| 영역 | 역할 | 과업 | 위계 |
|---|---|---|---|
| 바 슬롯 8px | 드문 상태 강조 (오더 이상, HD, 처리 후 변경) | 찾기(스캔) | 1차 |
| 체크 셀 76px (체크 44 + 표지 32) | 선택, 처리 상태 표지 | 일괄 처리, 찾기 | 1차 |
| DC 열 96px | 오더 상태 배지, 처리 후 변경 문장형 배지 | 찾기, 단일 행 보기 | 1차 |
| 약품명 | 처방 식별 | 단일 행 보기 | 1차 |
| 원안 열들(용법·용량 등) | 처방 내용 | 비교, 단일 행 보기 | 2차 |
| 검토자·감사자 칸 | 누가, 언제(이름·시각, BID 두 이름), "D/C 확인" 보조 텍스트 | 단일 행 보기 | 3차(보조) |
| 메모·이력·연동 아이콘, tooltip | 상세 | 단일 행 보기 | 3차 |

- **바 슬롯**은 늘 8px를 확보한다. 상태가 바뀌어도 내용이 밀리지 않게 하기 위해서다. 1배 바는 4px(왼쪽 정렬), 2배 바는 8px다.
- **처리 표지**는 독립 열이 아니라 체크 셀 안의 오른쪽 슬롯이다. 헤더에는 전체 선택 체크박스 옆에 작은 텍스트 "처리"만 둔다. 탭 영역은 체크 셀 전체(76 × 44px 이상)다(A-6).
- **DC 열**을 고정 영역에 넣고 폭을 96px로 넓힌다. 처리 후 변경의 문장형 배지를 담기 위해서다. 원안의 DC 열보다 넓어진다. ⚑ PM 확인 필요(Q-V2-03). 원안 열 순서에서 DC 열이 체크박스 바로 뒤에 있는지는 확인하지 못했다(M4 와이어 기준, 0.5).
- 검토자·감사자 이름은 **중립 텍스트(ink.secondary)** 로 쓴다. 설계서 v1.1의 파란 이름(X2)은 정리한다.

- 제2색약: 보라(HD)는 파랑 쪽으로, 빨강(처리 후 변경)과 앰버(오더)는 서로 비슷한 갈색 쪽으로 수렴할 가능성이 높다(일반 지식, 0.6). 그래서 **HD vs 감**은 표지 글자("HD"/"감")와 바의 유무로, **빨강 vs 앰버**는 폭, ⚠, 문구로 구분한다. ΔE 시뮬레이션은 스크립트 재검증 때 함께 계산해 주기를 요청한다.
- 눈부심: 모든 배경 틴트가 사라져도 바(≥4.1:1), 배지(≥5.2:1), 표지(≥5.0:1)가 남는다.

### 4. 상태 조합 매트릭스

#### 4-1. 겹침 우선순위 규칙

1. **행 배경과 좌측 바는 행마다 1개**다. 우선순위는 다음과 같다:
   `S-FL-03(활성) > S-OD-01~04 > S-WF-01 HD > S-WF-04 감사 틴트 > 없음(흰)`
2. **처리 표지(체크 셀)** 는 S-WF가 결정한다. 다른 무엇에도 가려지지 않는다.
3. **DC 배지**는 S-OD가 결정한다. 단, S-FL-03이 켜져 있으면 앰버 배지 대신 **빨강 문장형 배지**를 쓴다. 문장 안에 오더 값("D", "보", "D, 보", "반납")이 그대로 들어가므로 오더 정보는 사라지지 않는다.
4. **선택**은 외곽선과 체크 채움만 더한다. 바, 배경, 표지, 배지는 바꾸지 않는다.
5. **⚠ 아이콘**은 S-FL-03에서만 쓴다(행 배지와 헤더 배지).
6. 감사자·검토자 칸(스크롤 영역)은 기록을 늘 유지한다. S-FL-03 행에는 "감사 김약사(더미) 09:12 → D/C 09:40"처럼 두 시각을 함께 보여준다.

### 5. 환자 카드 헤더 롤업

```
┌ ▾ 701호 환자A(더미) · M/63   〔⚠ 확인 필요 1〕  D 1 · 보 1 · HD 1        감사 32/40 ▕████████░░▏ ┐
┌ ▸ 702호 환자B(더미) · F/71   〔D 2〕                                       감사 3/6   ▕███░░░▏    ┐
┌ ▸ 703호 환자C(더미) · M/55                                                감사 5/5 완료            ┐
┌ ▸ 704호 환자D(더미) · F/80   〔보 3〕                                       감사 대상 없음           ┐
```

**① 최고 주의 배지(1개)**
- 우선순위: `⚠ 확인 필요`(S-FL-03, 빨강) > `D`(S-OD-01, 앰버) > `보`(S-OD-02·03) > `반납`(S-OD-04) > `HD`(S-WF-01, 보라).
- 형식: 채움 배지 "{라벨} {건수}". 색은 행 규칙과 같다. 해당 상태가 하나도 없으면 배지를 두지 않는다.
- 셈 규칙: S-FL-03 행은 "확인 필요"로만 센다(D·보에서 중복으로 세지 않는다). "D, 보"(S-OD-03)는 "보"로 센다(차단 오더이므로). HD × 오더 이상 행은 오더 쪽으로 센다.

**② 나머지 건수**: 최고 배지에 쓰지 않은 범주를 위 순서대로 "D 1 · 보 1 · 반납 1 · HD 1" 형식의 `ink.secondary` 텍스트로 보여준다. 0건인 범주는 생략한다.

**③ 진행률**: `감사 {a}/{b}`
- b(대상) = S-OD-BLK(02·03·04)가 **아닌** 처방 행 수. v1 S-DAY 규칙을 그대로 쓰므로 D/C 단독(S-OD-01)도 분모에 들어간다(Q-V2-02).
- a(완료) = b에 속하면서 S-WF-04인 행 수. S-WF-03(BID 1/2)은 미완료로 센다(v1 Q-15).
- 단위는 처방 행이다(항암·TPN 묶음도 행 수로 센다).
- `a = b` 이고 확인 필요가 0건이면 "감사 {b}/{b} 완료". 확인 필요가 1건 이상이면 "완료"를 붙이지 않는다(v1 G-04).
- `b = 0`이면 "감사 대상 없음".
- 진행률 막대(선택 요소): 64 × 4px, 채움 `ink.secondary`, 바탕은 1px `ink.secondary` 테두리만. 색을 쓰지 않는다.
- 하루 단위(S-DAY)는 목록 상단에 같은 형식으로 둔다: "긴급 감사 287/300 · 확인 필요 2".

접힌 카드에서도 ①~③이 모두 보인다. 새 아이콘은 추가하지 않는다.

#### 6-2. 저장 확인창: D/C 포함 (G-02)

- **제목**: D/C 처방 2건이 포함되어 있습니다
- **본문**:
  > 아래 처방은 HIS에서 D/C(중단)된 상태입니다.
  > · 702호 환자B(더미) · 와파린정 2mg · D/C 09:40
  > · 705호 환자E(더미) · 약품K정(더미) · D/C 10:02
  > 포함해서 감사하면 'D/C 확인 후 감사'로 기록되고, BESTCare에 감사 서명이 전송됩니다.
- **버튼**: [D/C 2건 빼고 10건 감사 저장] (기본·포커스) / [12건 모두 감사 저장] / [취소]
- 동사는 액션에 따라 바꾼다: "검토 저장", "문의/HD 등록"(HD 등록에는 BESTCare 문장을 넣지 않는다).
- 목록이 5건을 넘으면 5건만 보여주고 "외 n건 보기"로 펼친다.
- 바깥 영역을 탭하면 [취소]와 같다.
- 버튼 색: 기본 버튼은 `ink.primary` 채움 + 흰 글자, 나머지는 테두리형이다. 빨강은 쓰지 않는다(J5).

**경고가 여러 개일 때(G-02 + G-05 + G-14)**: 확인창을 연달아 띄우지 않고 **하나로 합친다.**
- 제목: 저장 전에 확인할 처방이 있습니다
- 섹션 순서: ① D/C 2건(목록) ② 문의/HD 1건 — "감사하면 HD 기록은 이력에 남습니다" ③ "총 62건을 한 번에 감사합니다"(임계값 v1 Q-07 초과 시)
- 버튼: [D/C·HD 3건 빼고 59건 감사 저장] (기본) / [62건 모두 감사 저장] / [취소]
- 대량(③)만 해당하면: 제목 "62건을 한 번에 감사합니다", 버튼 [62건 감사 저장] / [취소].

**저장 결과 토스트**(경고 없음 또는 확인창 이후): "감사 저장 10건 · 제외 2건(D/C 2) [되돌리기]". 6초 동안 표시하며, 되돌리기는 같은 배치를 저장취소한다(G-14). 토스트는 `ink.primary` 배경 + 흰 글자다.
