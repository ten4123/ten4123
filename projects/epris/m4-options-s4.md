### OPT-S4-a 현행 v1.1 기준선

**한 줄 컨셉**: 설계서 v1.1 p.14~15와 원안 p.19~21 그대로. 접수 시간순 평면 목록, 저장하면 사라지고 다음 환자가 열린다. 진행률·알림·진입점은 없다.

```
1280 × 800dp (가로)
┌ ‹ 입원조제(긴급)  32병동 외 4건 ✎                                   🔍 환자번호로 검색   ⊞ ┐ 56

├ 좌 목록 ~300 ──────────────────┬ 우 처방전 ~980 ───────────────────────────────────────────┤
│ 접수시간  병동   환자명  등록번호 │ 환자A(더미) 0000-0001 41병동/B/12호실 …        ‹ ›          │ 헤더 ~88

├───────────────────────────────┴───────────────────────────────────────────────────────────┤

```

- **동작**: 행 탭 → 우측 처방전(전체 체크) → [감사저장] → 좌측에서 제거 + 다음 자동 열림 → ▶ = 상태 그대로 다음 → 끝나면 우측 빈 화면.
- **REF**: 기준선(원안·설계서 직접 근거). 대조용 REF-218(목록-상세).
- **가정**: 약사가 좌측 목록 길이로 남은 양을 짐작한다. 새 긴급은 [조회]나 화면 재진입으로 본다. 정규 화면에서는 긴급을 따로 열 필요가 없다.
- **장점**: 고객이 이미 본 화면이라 설명 비용과 재작업이 없다. 저장 = 사라짐이라 목록이 실제로 짧아진다.
- **비용**: 남은 건수와 하루 완료 여부를 셀 수 없다(F-6). ▶로 넘긴 건과 부분 감사한 건이 표시 없이 섞인다(누락 위험). 저장 직후 사라진 건을 다시 찾을 길이 없다. 새 긴급이 언제 들어왔는지 모른다. 기본 전체 체크는 D/C 포함 감사 위험이 있다(F11). 중분류는 하나만 고를 수 있다(R-045 ↻). 정규 화면 분기 조회 요구(R-006)를 채우지 못한다. 하단 버튼은 저장취소가 감사저장 바로 옆이다(X-1 위반).
- **익숙함 비용**: 없음(기준선).
- **기대 효과**: 속도 — 저장 = 다음으로 탭 수는 적다. 안전 — 낮음(전체 체크, 넘긴 건 추적 없음, 완료 판정 없음). 판단 — 우측 헤더에 판단 수치가 있다.
- **⚑**: 없음(기준선). 단 이 안을 고르면 R-006·R-069 미반영이므로 PM 공유가 필요하다.

### OPT-S4-b 시간대 섹션 + 제자리 완료 (최소 구조 변경)

**한 줄 컨셉**: 순서는 종이 순서(접수시간 > 병동 > 호실 > 이름) 그대로 두고, **1시간 단위 섹션 헤더**로 끊는다. 감사한 항목은 사라지지 않고 제자리에서 톤다운된다. "줄어드는 느낌"은 숫자와 시간대 막대가 만든다.

- 바꾸는 축: ① 시간대 섹션 ② "287/300 · 남은 13" + 시간대 막대 ③ 목록 끝 추가 + "새" 라벨 ④ 자동 다음 + 제자리 완료 + 토스트 되돌리기 ⑤ 정규 화면 오더 칩 배지 ⑥ 다중 칩 줄

```
1280 × 800dp (가로)
```

## 오케스트레이터에게

1. **대안 형태를 가르는 미확인 사실 5건**(§1 Q-1~Q-5). 특히 **Q-1(300건이 시간당인가 하루인가, 행인가 환자인가)** 에 따라 b의 시간대 막대와 f의 칼럼 의미가 달라진다. M7 질문지에 넣기를 권한다. 신뢰도 0.7.
2. **원안 F-4("저장하면 목록에서 사라진다")와 K-3(자동 재정렬 금지)의 관계**를 정해 주어야 한다. 이번 발산에서는 두 해석을 모두 냈다. b·d·f는 "제자리 완료"(사라지지 않음 = 원안 변경 ⚑), c는 "자기 저장 항목만 같은 자리 교체"(원안 유지). 소거가 K-3 위반인지는 내가 판정하지 않았다(M5 몫). 신뢰도 0.6.
3. **m6 v2 §8 S-UI-4 수정 반영**: 모든 와이어에서 열람 중 항목은 외곽선 + "열람 중" 텍스트만 쓰고 굵기를 바꾸지 않았다(m3 지적). c의 경과 시간 초과 bold는 처음부터 bold 폭 슬롯을 잡는 방식으로 적었다(REF-409). 신뢰도 0.7.
4. **진입점 색 공백**: 정규 화면 진입점이 쓸 수 있는 상태 색이 남아 있지 않다(빨강 = S-FL-03, 앰버 = 오더 이상, 보라 = HD, 파랑 = 감사, 청록 = 선택). 모든 대안이 텍스트·숫자로만 강조한다. 기준 시간 초과를 색으로 띄우자는 요청이 오면 토큰 추가 결정(DEC)이 필요하다. 신뢰도 0.65.
5. **S5 컴포넌트 의존**: a를 제외한 모든 대안의 우측(또는 시트·카드)은 S5 처방전 뷰 컴포넌트를 가정한다. S5 발산(m4-options-s5)에서 헤더 높이(이 문서는 72dp, 세로 88dp)와 ‹ n/N › 위치가 바뀌면 와이어 치수를 맞춰야 한다. 신뢰도 0.6.
6. **⚑ PM 확인 묶음(S4 신규)**: 실시간 유입(REF-204, 전 대안), 저장 후 제거하지 않음(b·d·f), 정렬 구조 변경(d, R-047), 분할 화면 폐기·세로 운용(e), 알림음(f), S1 화면에 진입점 공간 추가(c·d·f의 E2·E3). 기존 ⚑(K-6 D/C 기본 선택 제외, G-14 되돌리기)과 합쳐 묻기를 권한다.
7. 사용자 Try 안은 전달받지 못했다. 있으면 OPT-S4-u로 같은 형식에 추가하겠다.

## 요약
S4 긴급 큐를 HMW 3개로 바꾸고, 현행 기준선(a)을 포함해 대안 6개를 냈다. 시간대 섹션(b), 소거형 카운터(c), 중분류 묶음(d), 극단안으로 세로 1환자 카드(e)와 KDS 칼럼 보드(f)가 있다.
축은 큐 구조, 진행 표현, 새 유입, 자동 다음, 정규 화면 진입점, 중분류 필터 6개다. 유입·진입점·자동 다음은 바꿔 끼울 수 있는 모듈로 따로 정리했다(§9).
평가는 하지 않았다. 형태를 가르는 미확인 사실(300건의 단위, 동시 사용, 실시간 수신)과 원안의 "저장 = 사라짐" 해석은 오케스트레이터 몫으로 남겼다.

## 신뢰도
- 현행(F-1~F-8) 기술: 0.85. 설계서·원안 이미지를 직접 봤다. 해상도 때문에 열 이름 일부는 0.7이다.
- 치수(1280×800 프레임, 좌 320 / 우 959, 항목 56, 행 44): 0.5. 기기가 확정되지 않았고 dp 단위와 실제 해상도의 관계는 가정이다.
- 각 대안의 가정과 기대 효과: 0.35~0.5. 약사 관찰 전이라 모두 **가설**이다.
- 레퍼런스 매핑: 0.6. m3 §7 S4 보드의 채택 카드만 썼고, 원문은 다시 확인하지 않았다.

## 주의사항
- 이 문서는 발산이다. 6개는 서로 다른 구조이고, 순서는 우열이 아니다.
- 극단안 e·f는 원안의 분할 화면을 버린다. 계약 범위에 영향을 주므로 ⚑를 붙였다. 현실로 되돌아올 때 가져갈 조각(예: f의 칼럼 접힘 → b의 섹션 완료 표시, e의 다음 3명 띠 → c의 목록 상단)은 M5가 판단한다.
- 환자명과 등록번호는 모두 더미다(환자A~L, 0000-000n). 약사 이름도 더미다.
- 진행 줄의 분자·분모는 처방 행 단위(S-DAY)로 썼다. 목록 항목은 환자 단위다. Q-1이 풀리면 문구를 바꿔야 한다.
- m6 v2의 열람 중 bold 규칙은 m3 지적에 따라 와이어에서 빼고 그렸다. m6 본문은 아직 고쳐지지 않았다.
